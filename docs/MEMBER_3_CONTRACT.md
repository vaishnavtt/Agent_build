# Member 2 → Member 3 Integration Contract
### AI Requirement Analysis & Execution Plan Specification

This document defines the interface and data contract between **Member 2** (AI Requirement Analysis & Agent Architect) and **Member 3** (Workflow Generation Module).

---

## 1. Responsibilities Boundary

- **Member 2 (Agent Architect)**:
  - Ingests natural-language user descriptions.
  - Understands project objectives, constraints, inputs, and outputs.
  - Decomposes requirements into ordered, executable tasks with dependencies.
  - Identifies canonical workflow components (strictly from the 7 supported primitives).
  - Detects missing/ambiguous requirements and issues clarification questions.
  - **Does NOT generate React Flow visual nodes or canvas edges.**

- **Member 3 (Workflow Generator)**:
  - Ingests the structured execution plan generated by Member 2.
  - Converts ordered tasks (`tasks`) into React Flow nodes (`nodes`) with 2D coordinates `(x, y)` and node configs.
  - Transforms task dependencies (`dependencies`) into directed React Flow edges (`edges`).
  - Renders and persists the visual canvas graph.

---

## 2. JSON Schema & Data Contract

Contract version: `1.1.0`
Schema Definition: `shared/execution_plan.schema.json`

## 3. How Member 3 Should Consume the Plan

1. **Verify Plan Status**:
   - Check `status === "ready"`.
   - If `status === "needs_clarification"`, do not construct canvas nodes; display the clarification questions from `clarification_questions`.

2. **Map Tasks to React Flow Nodes**:
   - For each task in `plan.tasks`:
     - Node ID: `node-${task.task_id.toLowerCase()}` (e.g. `node-t1`, `node-t2`).
     - Node Type: `customWorkflow`.
     - Node Position: Compute horizontal layout using `execution_order`:
       `x: 100 + (task.execution_order - 1) * 280, y: 150`.
     - Node Data:
       ```json
       {
         "label": task.task_name,
         "componentType": task.component,
         "description": task.description,
         "status": "ready",
         "config": task.component_config_hints || {}
       }
       ```

3. **Map Task Dependencies to React Flow Edges**:
   - For each task in `plan.tasks`:
     - For each dep in `task.dependencies`:
       - Edge ID: `e-${dep.toLowerCase()}-${task.task_id.toLowerCase()}`.
       - Source: `node-${dep.toLowerCase()}`.
       - Target: `node-${task.task_id.toLowerCase()}`.
       - Animated: `true`.

4. **Component Types Guarantee**:
   Member 2 guarantees that every `task.component` strictly matches one of the 7 canonical components defined in `shared/node_definitions.json`:
   - `Input`
   - `LLM`
   - `Document Reader`
   - `Tool`
   - `Condition`
   - `Human Approval`
   - `Output`
